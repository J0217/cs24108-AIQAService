## 2. 后端启动

### 2.1 安装依赖

在项目根目录执行：

```powershell
python -m pip install -r requirements.txt
```

### 2.2 配置环境变量（可选）

```powershell
Copy-Item .env.example .env
```

`.env` 中与 E 模块有关的配置：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `API_KEYS` | `demo-api-key` | 开放 API 允许的 Key，多个用英文逗号分隔 |
| `WX_APPID` | 空 | 小程序 AppID；为空时后端使用开发态 mock openid |
| `WX_SECRET` | 空 | 小程序密钥，与 AppID 配套 |
| `SECRET_KEY` | 开发默认值 | Flask 会话密钥，部署前必须改 |
| `JWT_SECRET_KEY` | 开发默认值 | JWT 签名密钥，部署前必须改 |
| `AI_API_KEY` | 占位值 | 大模型 Key；不配置时使用本地模板兜底 |

注意：`.env.example` 中的 `DATABASE_URL` 当前不生效，数据库路径固定为 `instance/ai_qa_service.db`。这是当前代码的已知差距，切换 PostgreSQL 需要改模型的数据库初始化。

### 2.3 启动服务

```powershell
python backend/app.py
```

也可以使用：

```powershell
python -m backend.app
```

启动后监听 `http://localhost:5000`。首次启动会自动完成：

1. 在 `instance/` 下创建 `ai_qa_service.db` 并建 6 张表；
2. 创建管理员账号 `admin / admin123`；
3. 写入五类场景的初始快捷回复模板；
4. 写入一条欢迎公告。

控制台出现 Flask 启动信息即表示成功。停止服务按 `Ctrl+C`。

## 3. 开放 API 使用

### 3.1 鉴权

所有 `/api/v1/*` 请求必须携带：

```
X-API-Key: demo-api-key
```

缺少或无效统一返回 HTTP 401。Key 来自 `.env` 的 `API_KEYS`，不要在代码或文档中写真实生产 Key。

### 3.2 接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/chat` | 发送问题，返回回答、置信度、是否模板命中 |
| GET | `/api/v1/quick-reply` | 获取快捷回复，可按 `scene_type`、`category`、`keyword` 过滤 |
| GET | `/api/v1/announcement` | 获取优先级最高的最新公告 |
| GET | `/api/v1/stats` | 获取用户、会话、消息统计 |

### 3.3 调用示例

```powershell
curl.exe -X POST http://localhost:5000/api/v1/chat `
  -H "Content-Type: application/json" `
  -H "X-API-Key: demo-api-key" `
  -d "{\"question\":\"如何查询订单？\",\"session_id\":\"demo-001\",\"scene_type\":\"ordering\"}"
```

成功返回：

```json
{
  "code": 200,
  "message": "请求成功",
  "data": {
    "session_id": "demo-001",
    "question": "如何查询订单？",
    "answer": "……",
    "confidence": 0.95,
    "is_quick_reply": 1,
    "response_time": 7.3,
    "message_id": 1
  },
  "timestamp": "……"
}
```

### 3.4 错误码

| HTTP 状态 | 场景 | 返回 message |
|---|---|---|
| 200 | 成功 | 请求成功 / 获取成功 / 暂无公告 |
| 400 | `question` 缺失或 strip 后为空 | 问题内容不能为空 |
| 401 | 未带 `X-API-Key` | 缺少API Key |
| 401 | Key 不在 `API_KEYS` 中 | API Key 无效 |

四个接口的字段与场景类型以 `README.md` 和源码为准；改字段前按变更流程通知使用方。

## 4. 小程序运行

1. 打开微信开发者工具，选择“导入项目”，目录选 `miniprogram`。
2. AppID 当前为 `touristappid`（游客模式），只能预览界面，不能完成真实微信登录。
3. 确认 `project.config.json` 中 `urlCheck` 为 `false`，否则本地 HTTP 请求会被拦截。
4. 确认 `miniprogram/app.js` 的 `baseUrl`：
   - 开发者工具模拟器：`http://localhost:5000/api`
   - 真机调试：改成电脑局域网 IP，如 `http://192.168.1.10:5000/api`，并保证手机与电脑同一网络
5. 编译后进入首页，点击登录。后端未配置 `WX_APPID`/`WX_SECRET` 时使用 mock openid，仍可完成登录、会话和消息流程。
6. 进入对话页后依次验证：切换场景、点击快捷问题、发送消息、查看回复、返回首页看公告数。

真实 AppID 的补充步骤：在微信公众平台申请小程序或测试号，把 AppID 填入 `project.config.json`，把 `WX_APPID`、`WX_SECRET` 填入 `.env`，重启后端，再在真机上验证 `wx.login` 换取 JWT 的完整链路。

## 7. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `/api/v1/*` 返回 401 | 未带 Key 或 Key 不在 `API_KEYS` | 检查请求头与 `.env`，改完重启 |
| `/api/v1/chat` 返回 400 | `question` 为空或只有空格 | 传非空问题字符串 |
| 小程序请求失败 | `baseUrl` 不是本机地址，或后端未启动 | 先确认浏览器能打开服务，再检查 `baseUrl` |
| 真机请求失败 | 用了 `localhost` | 改成电脑局域网 IP，检查防火墙 |
| 微信登录失败 | AppID/Secret 未配置或无效 | 游客模式先预览，真实登录需配置测试号 |
| 回复像固定话术 | 未配置 AI Key，走了模板兜底 | 配置 `AI_API_KEY` 后重启；或接受模板回复 |
| 端口 5000 被占用 | 其他进程占用 | 结束占用进程或修改启动端口 |
| 想重置数据 | 需要干净的演示数据 | 停止服务，删除 `instance/ai_qa_service.db`，重启自动重建 |

## 8. 安全与提交注意事项

1. `.env` 不提交仓库，仓库只保留 `.env.example`。
2. 部署前修改 `admin` 默认密码、`SECRET_KEY`、`JWT_SECRET_KEY`、`API_KEYS`。
3. 开放 API 的 Key 只发给确定的调用方；泄露后立即在 `.env` 中替换并重启。
4. 提审小程序前删除本地调试地址，改为已备案的 HTTPS 域名。

## 二、需求与接入

**Q5：小程序端和开放 API 的鉴权有什么不同？**
A：小程序走 JWT，登录后把 `Authorization: Bearer <token>` 注入请求头；开放 API 走 `X-API-Key`，Key 由 `.env` 的 `API_KEYS` 配置，多个用逗号分隔。两者面向的对象不同：JWT 面向具体用户，API Key 面向外部系统。见 §1.5、表 1-3。

**Q6：开放 API 有哪几个接口？**
A：`POST /api/v1/chat`、`GET /api/v1/quick-reply`、`GET /api/v1/announcement`、`GET /api/v1/stats`，全部在 `api.py` 的 `before_request` 中统一校验 Key。见 §1.3、README。

**Q7：为什么把鉴权放在 `before_request`，而不是每个函数里写一遍？**
A：放在 `before_request` 能覆盖 `/api/v1/*` 全部路径，新增接口自动受保护，避免漏写。缺失 Key 返回 401“缺少API Key”，Key 无效返回 401“API Key 无效”。这是一个已执行的变更 C-001。见 §12.4、表 13-2。

**Q8：小程序主流程是什么？**
A：`wx.login` 拿 code → `POST /api/auth/wx-login` 换 JWT → 首页加载公告 → 进入对话页 → 创建或复用会话 → `POST /api/chat/conversations/:id/messages` 取回复 → 读取历史。见 §2.3、§4.1。

**Q9：没有真实 AppID 怎么验证登录？**
A：当前 `project.config.json` 用 `touristappid` 游客模式，只做开发者工具界面预览；后端未配置 `WX_APPID`/`WX_SECRET` 时使用开发态 mock openid，能跑通登录、会话和消息。真机登录没有验证，报告里没有写成已完成。见 §7.2、表 1-4 的 E6-1。

**Q10：E 模块依赖哪些内部接口？**
A：8 个：微信登录、用户信息、会话列表、新建会话、消息收发、场景列表、快捷回复、公告列表与已读，分别由 A、B、D 提供。E 只通过 HTTP 路由调用，不直接读别人的表。见 表 2-3。

## 四、成本、质量、资源

**Q16：项目成本怎么算？**
A：人力单价 50 元/人时。全项目 123 人时、6,150 元；E 模块 28 人时、1,400 元。AI 接口可选 100 元，不可预见费 625 元，成本基线 6,875 元。见 表 5-1、表 5-2。

**Q17：为什么不可预见费是 625 元？**
A：人力 6,150 元加 AI 费用 100 元为 6,250 元，按 10% 计提 625 元，合计 6,875 元。见 §5.3。

**Q18：质量目标有哪些量化指标？**
A：开放 API 鉴权覆盖 4/4；鉴权分支用例 3/3；E 模块接口用例 21/21（冒烟 7 + 改进项 14）；模板命中置信度不低于 0.75，实测订单问题 0.95；本地模板命中单次 7.306 毫秒；操作手册可复现。见 表 6-1。

**Q19：测试怎么跑？结果是什么？**
A：`python test/test_e_module.py -v` 7 条、`python test/test_improvements.py -v` 14 条，共 21 条用例全部通过，2026-11-11 运行耗时 0.700 秒 + 1.226 秒。覆盖鉴权缺失、Key 错误、模板命中、空白问题、三个查询接口、登录与场景、会话消息主链路，以及 AI 判定、越权、限流、异常分支。见 §6.2。

**Q20：你们发现过什么缺陷？**
A：共 3 个。D-001：`/api/v1/chat` 传入只含空格的问题时返回 200，修复为先 strip 再判空、返回 400。D-002：`_ai_configured` 把空字符串列入占位前缀，导致任意 Key 都被判为未配置、大模型从未被调用，修复为精确匹配占位值集合。D-003：弱匹配模板会覆盖大模型结果，修复为已配置真实 Key 时以大模型结果为准。三个缺陷均有回归用例固化。见 表 6-3。

**Q21：三套环境怎么配？生产做了吗？**
A：dev 用 `DevelopmentConfig` + `instance/ai_qa_service.db`，`python backend/app.py` 启动；test 用 `TestingConfig` + 临时 SQLite + `test_client`；prod 只有 `ProductionConfig`，计划 gunicorn + PostgreSQL，当前未部署。数据库路径目前在模型里固定，切 PostgreSQL 要改初始化代码。见 表 7-2、§16.3。

**Q22：为什么选 Flask + Peewee + SQLite？**
A：轻量、启动快、SQLite 零配置，适合课程原型和本机演示；代价是生产并发和迁移能力有限，所以生产方案留了 PostgreSQL。见 表 16-2。
